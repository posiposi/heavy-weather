# 概要

ユーザーから引数で受け取った依頼内容を調査する。
調査作業はサブエージェントに委任し、結果を統合して報告する。

## 調査フロー

### 1. 調査計画の立案

依頼内容を分析し、必要な調査の種類を判断する。

| 調査種別 | サブエージェント | 使用場面 |
|---|---|---|
| コード調査 | `code-investigator` | コードベースの該当箇所・実装詳細の調査 |
| ログ調査 | `log-investigator` | エラーログ・テスト結果・CI状況の調査 |
| Web調査 | `web-researcher` | 公式ドキュメント・API仕様・エラー解決策の調査 |

> **補足**: 本プロジェクトはまだ実装コードが存在しないため、調査依頼の多くは Web 調査（外部天気 API / AWS 各サービスの仕様）と設計書 `heavy-weather-architecture.md` の読解になる。設計書 §11「未確認事項」に挙がっている項目（天気 API のレスポンス仕様・降水確率の粒度・レート制限・商用利用可否・タイムゾーン、RDS Proxy / Aurora 系の料金、SES の送信レート上限、ユーザー管理の形態）は、一次情報での確認が必要な既知の調査対象である。

### 2. サブエージェントの起動

- 調査が複数の種別に渡る場合はサブエージェントを**並列実行**する
- 各サブエージェントには調査対象を明確に指示する

### 3. 調査結果の統合・出力

サブエージェントの調査結果を統合し、以下を行う：

1. メインコンテキストでユーザーに調査結果を表示する
2. `.claude/tmp/user-investigation-request/` 配下にレポートファイルを保存する

## レポートファイルの保存

### ファイル命名規則

```
YYYYMMDD-{調査概要}.md
```

- `YYYYMMDD`: 調査実施日
- `調査概要`: 調査内容を簡潔に表す英語のケバブケース

**例:**
- `20260725-open-meteo-hourly-precipitation.md`
- `20260725-eventbridge-putevents-partial-failure.md`
- `20260725-ses-production-access-sending-rate.md`

### レポート構成

```markdown
# {調査概要}

- 調査日: YYYY-MM-DD
- 依頼内容: {ユーザーの依頼内容}

## 調査結果

### {調査項目1}

- 結論
- 根拠・詳細

### {調査項目2}

...

## 参照情報

- 関連ファイル・URL等
```
